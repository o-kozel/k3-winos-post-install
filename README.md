# k3 WinOS Post install

Налаштування свіжовстановленої Windows 11: приватність і телеметрія, служби, видалення зайвих AppX, програми,
PowerShell 7 з oh-my-posh, курсори. Усе виконується однією командою, з журналом і підсумковою таблицею.

> **Стан перевірки.** Код покрито тестами (див. «Тести») і прогнано в режимі `-WhatIf`. На чистій системі з
> правами адміністратора повний прогін ще **не робився** - перший раз запускайте на віртуальній машині зі
> знімком.

## Швидкий старт

Від імені **адміністратора**, у Windows PowerShell 5.1 або PowerShell 7:

```PowerShell
# 1. Спершу сухий прогін: показує, що було б зроблено, нічого не змінюючи
powershell -NoProfile -ExecutionPolicy Bypass -File .\Invoke-PostInstall.ps1 -WhatIf

# 2. Справжній прогін
powershell -NoProfile -ExecutionPolicy Bypass -File .\Invoke-PostInstall.ps1
```

`-ExecutionPolicy Bypass` потрібен, бо на клієнтських Windows політика за замовчуванням забороняє запуск
локальних скриптів.

**Порядок.** Єдина точка входу - `Invoke-PostInstall.ps1`. Задачі з `tasks\` виконуються за числовим префіксом
у назві файлу (`00-`, `10-`, `70-` ...). Раніше порядок був неявним (`Configuration.ps1`, потім
`Software_installation.ps1`); тепер він записаний у назвах файлів.

Якщо оркестратор запущено під PowerShell 7, він сам перезапускається у Windows PowerShell 5.1: деякі команди
(`Checkpoint-Computer`, модуль Appx) у 7-й версії недоступні.

## Передумови

* Windows 10/11 (налаштування розраховано на Windows 11; на Windows 10 частина нічого не зробить - буде попередження).
* Права адміністратора (без них скрипт відмовляється на старті).
* Інтернет: Chocolatey, winget, O\&O ShutUp10, тема oh-my-posh. Без нього працюють реєстр, служби, живлення.

## Параметри

| Параметр        | Що робить                                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------------------------ |
| `-WhatIf`       | Сухий прогін. **Увага:** старий `Configuration.ps1` не вміє `-WhatIf` і в такому режимі пропускається цілком |
| `-Only <імена>` | Виконати лише ці задачі (ім'я файлу без номера й розширення), напр. `-Only Services,Cursors`                 |
| `-Skip <імена>` | Пропустити задачі, напр. `-Skip Debloat`                                                                     |
| `-NoCheckpoint` | Не створювати точку відновлення (для повторних прогонів)                                                     |
| `-LogDirectory` | Куди писати лог (за замовчуванням `C:\Support\Logs`)                                                         |

Невідома назва в `-Only`/`-Skip` - помилка зі списком доступних, а не мовчазне «нічого не виконано».

## Що робить кожна задача

| №  | Задача          | Дія                                                                                                                                                                                                                                |
| -- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 00 | `Checkpoint`    | Вмикає відновлення системи, створює точку відновлення; тимчасову зміну `SystemRestorePointCreationFrequency` повертає назад                                                                                                        |
| 10 | `Configuration` | Старий лінійний скрипт: F8-меню завантаження, ліміт тіньових копій, таймери живлення, NBT-NS, SMB (підпис **і шифрування**), блокування акаунта після 5 помилок, O\&O ShutUp10 (телеметрія й приватність), твіки Explorer і пошуку |
| 70 | `Services`      | Тип запуску служб за `data\services.psd1`; `Disabled` ще й зупиняє службу                                                                                                                                                          |
| 80 | `Debloat`       | Видаляє AppX за `data\appx-remove.psd1` для всіх користувачів і з образу системи                                                                                                                                                   |
| 90 | `Software`      | Chocolatey (лише якщо немає), реєстрація winget, пакети з `data\packages.psd1`                                                                                                                                                     |
| 92 | `Autostart`     | Завдання планувальника для SuperF4 - лише якщо знайдено справжній `SuperF4.exe`                                                                                                                                                    |
| 94 | `AppTelemetry`  | Вимикає телеметрію у файлах налаштувань користувача: VS Code, Claude Code, Codex CLI. Наявні налаштування доповнює, оригінал зберігає як `*.postinstall.bak`. Файли - у профілі того, хто запустив скрипт                          |
| 95 | `Shell`         | PowerShell 7 (оновлюється через Microsoft Update), oh-my-posh, тема, Nerd Font, Terminal-Icons, Windows Terminal за замовчуванням на pwsh, профіль                                                                                 |
| 96 | `Cursors`       | Курсори macOS (див. нижче)                                                                                                                                                                                                         |

> Позначки «RP §…», «WCS …», «Етап N» у коментарях коду й даних - посилання на внутрішню специфікацію
> проєкту, яка не публікується; їх можна ігнорувати.

## Підсумок прогону та журнал

Наприкінці друкується таблиця `Task / Status / Seconds / Note`:

| Статус    | Значення                                                                                     |
| --------- | -------------------------------------------------------------------------------------------- |
| `OK`      | Виконано                                                                                     |
| `WARN`    | Виконано, але частина кроків не вдалася (у `Note` - які саме); решта не постраждала          |
| `FAILED`  | Задача впала; **інші задачі це не зупиняє**. Код виходу скрипта тоді `1`                     |
| `WHATIF`  | Сухий прогін                                                                                 |
| `SKIPPED` | Виключена через `-Only`/`-Skip`, або задача сама пропустилась (напр., немає архіву курсорів) |

Повний транскрипт - `C:\Support\Logs\postinstall_РРРР-ММ-ДД_ггммсс.log` (окремий файл на кожен прогін, щоб
порівнювати їх між собою).

Скрипт ідемпотентний: повторний запуск друкує переважно `Skip` (уже встановлено) і майже нічого не змінює.

## Дані, які можна редагувати

Списки винесено з коду; кожен файл читається через `Import-PowerShellDataFile`, у них можна лишати коментарі.

| Файл                     | Вміст                                                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `data\services.psd1`     | Служби: `Name`, `Startup` (`Automatic`/`Manual`/`Disabled`), `Comment`. Закоментовані записи - свідомі рішення «не чіпати», їх не видаляйте |
| `data\appx-remove.psd1`  | Шаблони AppX для видалення. Пакети для ігор (`GamingServices`, `Xbox*`) закоментовані навмисно                                              |
| `data\packages.psd1`     | Пакети: `Id`, `Source` (`choco`/`winget`), `Params`. winget потребує **повного** Id (`Видавець.Пакет`)                                      |
| `data\cursors.psd1`      | Варіант курсорів: покоління, тінь, розмір                                                                                                   |
| `data\manual-steps.psd1` | Ручні кроки після прогону: `Group`, `Title`, `How`, `Task` (крок показується, лише якщо задача виконувалась)                                |

**Кодування.** Усі `.ps1`/`.psm1`/`.psd1` з кирилицею мають бути збережені як **UTF-8 з BOM**: Windows PowerShell
5.1 читає файл без BOM як ANSI, і текст (а інколи й лапки) ламається. Тест це перевіряє.

## Попередження

* **Точка відновлення не покриває видалення AppX.** Відкотити `Debloat` через відновлення системи не вийде -
  застосунки доведеться ставити з Microsoft Store.
* `Debloat` видаляє пакети **для всіх користувачів** (`-AllUsers`) і з образу системи. Повторний прогін видалить
  знову все, що збігається зі списком: якщо застосунок звідти встановлено свідомо - закоментуйте його рядок.
* **SMB:** `Configuration` вмикає обов'язковий підпис і **шифрування** (`EncryptData`) на сервері SMB. Це може
  відрізати старі NAS/пристрої без SMB 3.x і знижує швидкість. Зараз ввімкнено завжди (винесення в опцію - у плані).
* `DiagTrack` (телеметрія) переводиться в `Disabled`.
* Твіки, які раніше **мовчки не застосовувались** через відсутні ключі реєстру, тепер працюють. Тому перший
  прогін краще робити на віртуальній машині зі знімком, а не відразу на робочій.
* O\&O ShutUp10 завантажується з інтернету й запускається з правами адміністратора; перед запуском перевіряється
  валідність цифрового підпису (ім'я видавця поки не перевіряється).

## Що зробити вручну після прогону

Наприкінці прогону скрипт сам друкує, що зробити вручну і як, після підсумкової таблиці. Той самий текст
зберігається поруч із журналом: `C:\Support\Logs\postinstall_<дата>_manual-steps.txt`. Кроки для задач, пропущених
через `-Only`/`-Skip`, не показуються.

Перелік ведеться в одному місці: [data/manual-steps.psd1](data/manual-steps.psd1). Розділи:

* **Телеметрія і приватність** - першою: перевірка Windows і того, що змінила задача `AppTelemetry`, а також те,
  що скрипт вимкнути не може (перемикачі в інтерфейсах і акаунтах): навчання моделей у Claude і ChatGPT,
  Antigravity, Brave, PowerToys, Discord, Podman Desktop, UniGetUI;
* **Драйвер GPU і залізо** - DDU → NVCleanstall, MUX, режим живлення, екран, Nahimic / Lenovo Vantage з Microsoft Store;
* **Система** - WSL2 для Podman, Autoruns, DNS через HTTPS, Контроль пам'яті;
* **Програми** - вхід в облікові записи, пакети, які могли не встановитись, блокування реклами.

## Курсори

Курсори macOS. **Архів не входить до репозиторію**: це чужі курсори, похідні від Apple (умови - у `LICENSE.md` усередині
архіву). Завантажте [macOS Cursors Megapack](https://github.com/antiden/macOS-cursors-for-Windows) (релізний архів
`macOS-cursors-for-Windows-0.5.zip`) і покладіть zip у `assets\cursors\`. Без архіву задача `Cursors` має статус
`SKIPPED` і нічого не змінює. З архівом вона сама:

1. бере варіант із `data\cursors.psd1` (з 12 доступних в архіві);
2. копіює файли в `C:\Windows\Cursors\<тека варіанта>`;
3. реєструє схему в `HKCU\Control Panel\Cursors\Schemes`, робить її поточною;
4. застосовує без перезавантаження (`SystemParametersInfo`).

Налаштування діють для користувача, під яким запущено скрипт. Штатний `Install.inf` не використовується свідомо:
він дописує в `HKLM\...\Runonce` відкриття вікна «Властивості миші». Інший варіант - змініть `data\cursors.psd1`
і запустіть `-Only Cursors`. Вибір за замовчуванням (`Sierra and newer` / `No Shadow` / `Normal`) - припущення.

## Тести

```PowerShell
Invoke-Pester .\tests
```

Достатньо Pester 3.4, що є у Windows PowerShell 5.1. Тести перевіряють: цілісність даних (дублікати, допустимі
значення, захищені пакети), назви й префікси задач, узгодженість модуля, **BOM у файлах з кирилицею**, відсутність
відомих пасток (`Select-Object -First`, прямих `Set-ItemProperty` і нативних викликів без перевірки коду виходу),
формат конфігу O\&O, робочі посилання в документації та роботу хелперів. Написано без `Should`, щоб працювали і
в Pester 3.4, і в Pester 5; у Pester 5 їх ще не запускали.

## Структура

````
Invoke-PostInstall.ps1      єдина точка входу (оркестратор)
Configuration.ps1           старий лінійний скрипт; виконується задачею 10-Configuration
modules\PostInstall\        хелпери: Write-Step, Set-RegValue, Invoke-Native, Set-ServiceStartup,
                            Get-VerifiedDownload, Install-AppPackage, Invoke-LegacyScript, ...
tasks\                      задачі за числовими префіксами
data\                       списки: служби, AppX, пакети, курсори
assets\cursors\             сюди кладеться архів курсорів (у git не потрапляє)
PowerShell profile\         профіль pwsh і налаштування Windows Terminal
tests\                      Pester-тести```

## Якщо щось пішло не так

* «running scripts is disabled» - запускайте з `-ExecutionPolicy Bypass`, як у прикладі вище.
* `Debloat` падає з «Access is denied» - термінал не від адміністратора.
* Задача має статус `WARN`/`FAILED` - причину видно в колонці `Note` і в журналі в `C:\Support\Logs`.
* `Cursors` зі статусом `SKIPPED` - у `assets\cursors\` немає архіву (див. «Курсори»).
* Кракозябри замість кирилиці в повідомленнях - файл збережено без BOM (див. «Кодування»).
